## Scope and Ownership

AllYouNeedIsWheel scans the user's Moomoo watchlist for the top 3 cash-secured put and covered-call opportunities ranked by executable return on deployed capital per day, via local Moomoo OpenD. Signals-only: it never places, modifies, or cancels orders; outputs are manual copy-to-ticket suggestions. The scan universe is the watchlist union, never a broad market scan.

- `app.py` — Flask application factory, config load, SQLite data layer, one-screen dashboard, redirects for retired /portfolio and /options paths. Runtime services start only via explicit entry points (`run_api.py`, `python app.py`); importing never opens the DB or starts threads.
- `config.py` — application defaults and environment overrides, including the wheel risk preset default.
- `api/` — route blueprints and service orchestration (run, settings, watchlist, options, portfolio, roll pressure, alerts, earnings, ledger, source policy); `api/services/recommendation_ranking.py` owns shortlist ordering.
- `core/` — trading, scoring, connection, cache, wheel runner, immutable run model, presets, exit playbook, growth math, decision logic.
- `db/` — SQLite schema, migrations, pooling, repositories.
- `frontend/` — Jinja templates, CSS, static assets, browser JS for the one-screen dashboard.
- `tests/` — Python, frontend, fixture, and e2e verification.
- `.github/` — GitHub Actions workflows.
- `core/scheduler.py` and out-of-scope features (LLM, macro, catalyst, dynamic screening, long options) were removed in the 2026-08-02 consolidation; Docker packaging was also removed (Windows/loopback single-process only); see `docs/migration-ledger.md`.
- `README.md`, `API.md`, `SCORING.md`, `CHANGELOG.md`, and `OVERARCHING GOAL.txt` are durable human docs; update only when their public contracts or user-facing behavior change.

## Constraints

- Signals-only workflow: no autonomous order placement or execution behavior, ever.
- Structurally read-only: `core/broker_protocol.py` forbids unlock/order/cancel/modify members in runtime code; `readonly=False` is rejected; tests enforce this (`tests/test_no_execution_surface.py`). Keep live-trading safety gates intact — `REAL` plus `readonly=false` stays explicitly guarded, and `REAL` requires a configured `account_id` (never "the first account").
- Moomoo/OpenD is the sole source of truth for portfolio, positions, account capital, option chains, and tradeable broker data. Never introduce mock, fake, or simulated portfolio data into production behavior. Moomoo-only actionability: external data may diagnose but never create a pick; complete-union coverage and fresh Moomoo quotes gate copy actions, and stale broker time blocks actionable candidates while the market is open. Runs that cannot fit the OpenD quota are labeled `planning` — never silently truncated.
- Shortlist ordering after hard gates is descending executable return on deployed capital per day (`capital_velocity_per_day`), then descending executable-bid premium per day as tie-break, then canonical ticker, expiration, strike, option type (see `rank_key` and SCORING.md "Authoritative order of precedence"). Quality/event tiers, midpoint, and composite score are display-only and never gate or influence ordering.
- Keep the immutable run contract: one persisted `WheelRunSnapshot` per refresh, published atomically; refresh attempts are separate and never relabel old data.
- Presets are versioned and immutable; effective values are read-only in the UI.
- Import direction is acyclic: `core` must not depend on `api`; `db` may depend on `core`; `api.services` may depend on `core` and `db`; `api.routes` call services rather than duplicating business logic. Use existing service factories and route patterns; no global runtime state.
- Keep expensive broker and market-data calls behind the existing cache, rate-limit, and source-policy mechanisms.
- Prefer deterministic pure helpers for scoring, risk, and formatting so tests run without broker connectivity. Preserve Windows local-run ergonomics (OpenD on Windows, loopback-only).
- Never commit secrets, `.env` files, broker credentials, local databases, logs, caches, virtualenvs, generated bytecode, `plan.md`, or `.pi-subagents/`.
- No push, deploy, publish, merge, or destructive actions without explicit authorization (V10 §1). For auth/payment/trust-boundary changes, state that human security review is required. Security controls must be enforced by implementation, not guidance alone.

## Verification

- `.venv` is the canonical local Python environment, created and used through `start_local.ps1` via `uv sync --locked --all-groups`; `uv.lock` is the dependency source of truth. Remove any stale top-level `venv/` directory — it is git-ignored and can hide dependency drift.
- Python lint/format: `uv run ruff check .` and `uv run ruff format --check .`
- Python tests: `uv run python scripts/ci_pytest.py tests/ -q` (or `pytest tests/` directly).
- Frontend unit tests: `npm test` (vitest run).
- E2E smoke: `npm run test:e2e` (Playwright; needs the app on 127.0.0.1:8000 and `npx playwright install chromium`; asserts dashboard scaffolds, the read-only signal, and no execution-capable controls).
- Run the narrowest relevant pytest/Vitest file first, then broaden when touching shared contracts.
- Manual UI/OpenD smoke steps are documented in `tests/README.md`; exercise them for dashboard and OpenD-state changes. Unit tests require no live OpenD.
