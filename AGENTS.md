# DOX Framework

DOX is installed here as an `AGENTS.md` hierarchy. These files are binding work contracts for AI agents working in this repository.

## Core Contract

- Read this root `AGENTS.md` before editing.
- Identify every file or folder you expect to touch.
- Walk from the repository root to each target path and read every `AGENTS.md` found along the way.
- If docs conflict, the closer `AGENTS.md` controls local work details, but no child doc may weaken project-wide rules.
- After meaningful changes, update the closest owning `AGENTS.md` when purpose, ownership, contracts, workflows, verification, or durable structure changed.
- Keep DOX docs concise and operational. Document stable contracts, not diary entries.

## Purpose

AllYouNeedIsWheel is a local signals-only options dashboard for the Wheel Strategy using Moomoo OpenD as the source of truth. It surfaces cash-secured put, covered call, put, and call signals so the user can review opportunities in-app and place trades externally. The app favours to the aggressive side for max upside.

## Project-Wide Rules

- Preserve the signals-only workflow. Do not add autonomous order placement or execution behavior.
- Use Moomoo/OpenD as the source of truth for portfolio, positions, account capital, option chains, and tradeable broker data.
- Never introduce mock, fake, or simulated portfolio data into production behavior.
- Keep live-trading safety gates intact. `REAL` plus `readonly=false` must remain explicitly guarded.
- Prefer lean changes that improve signal quality, correctness, observability, or feedback speed.
- Delete duplication before adding abstractions. Do not reduce capability or safety to make code smaller.
- Treat `README.md`, `API.md`, `SCORING.md`, `CHANGELOG.md`, and `OVERARCHING GOAL.txt` as durable human docs. Update them only when their public contracts or user-facing behavior actually change.
- Do not commit secrets, local databases, broker credentials, logs, caches, virtualenvs, or generated bytecode.

## Architecture Map

- `app.py` creates the Flask application, loads connection config, initializes the SQLite-backed data layer, starts background health/scheduler work, and serves top-level pages.
- `config.py` owns application defaults and environment overrides.
- `api/` owns Flask app setup, route blueprints, and service orchestration.
- `core/` owns reusable trading, scoring, connection, cache, scheduler, and decision logic.
- `db/` owns SQLite schema, migrations, pooling, and repositories.
- `frontend/` owns Jinja templates, CSS, images, and browser JavaScript.
- `tests/` owns Python, frontend, fixture, and e2e verification.
- `.github/` owns GitHub Actions workflow automation.
- `docker/` owns OpenD container support used by the Docker Compose stack.
- `Dockerfile` and `docker-compose.yml` own local container packaging and service wiring.

## Work Guidance

- Keep import direction acyclic: `core` should not depend on `api`; `db` may depend on `core`; `api.services` may depend on `core` and `db`; `api.routes` should call services rather than duplicate business logic.
- Use existing service factories and route patterns instead of creating global runtime state.
- Keep expensive broker, market-data, and LLM calls behind existing cache, rate-limit, and source-policy mechanisms.
- Prefer deterministic pure helpers for scoring, risk, and formatting logic so tests can exercise them without broker connectivity.
- Preserve Windows local-run ergonomics because the app is designed around OpenD on Windows.

## Verification

- Python unit/integration tests: `pytest tests/`
- Frontend unit tests: `npm test`
- For focused work, run the narrowest relevant pytest/Vitest file first, then broaden when touching shared contracts.
- Manual UI smoke coverage is documented in `tests/README.md`; use it for dashboard, portfolio, rollover, and OpenD-state changes.
