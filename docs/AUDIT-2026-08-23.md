## Verdict

structural guarantees verified PASS in code: signals-only/read-only surface,
Moomoo-only actionability, no mock data, premium-velocity-primary ranking,
watchlist-union scope, immutable run snapshots, versioned-immutable presets,

stale DOX docs, and execution-flavored UI remnants behind. Two genuine
correctness bugs and one API contract bug were found. The documented lint gate

## B. FINDINGS (prioritized)

### HIGH

- **F-H1 [high] `core` imports from `api` — breaks the binding acyclic-import
  rule.** `core/wheel_runner.py:226-227`:
  `from api import get_service` / `from api.services.portfolio_scoring import …`.
  Root `AGENTS.md`: "Keep import direction acyclic: core should not depend on

  contract.** `api/routes/alerts.py:37-41` passes `extra={...}` to
  `error_response`, which merges kwargs into the body

  top-level `error_code`/`opend_status`. Every other OpenD gate emits them

  broker-unavailable state.

### Correctness bugs (med)

- **F-C1 Live-quote staleness silently never reaches confidence scoring.**
  `_is_quote_stale` reads key `quote_timestamp`
  (`core/wheel_decision.py:1202`) but live chains emit `update_time` /
  `quote_fetched_at_utc` (`connection_manager.py:875-876`); only persisted
  chains get stamped (`options_data.py:459-462`). Result: `is_stale` fed to
  confidence is always False for live quotes. (The separate hard gate at
  `wheel_decision.py:434-443` correctly uses `update_time`.) Fix: fall back to
  `update_time`.
- **F-C2 Exit verdicts dropped from persisted snapshots.**
  `decision.exit_verdict, decision.exit_reasons = ...`
  (`core/wheel_decision.py:1112`) assigns attributes that are not dataclass
  fields, so `to_dict()` excludes them; `WheelRunner` persists `to_dict()`
  (`wheel_runner.py:239`). Fix: declare both as dataclass fields.
- **F-C3 Refresh-All double-fires per click.** Delegated handler
  (`options-table-events.js:349-390`) plus direct listeners on the same buttons
  (:451-486) ⇒ two concurrent full refresh loops against rate-limited OpenD.
- **F-C4 `needsMigration` ReferenceError silently aborts saved-setting
  restore.** Undeclared identifier read at
  `frontend/static/js/dashboard/options-table-state.js:140`; surrounding
  try/catch hides it.
- **F-C5 Raw exception text bypasses `SANITIZE_ERRORS`** on two 500 paths:
  `api/routes/portfolio.py:193`, `api/routes/roll_pressure.py` final handler.
- **F-C6 Migration failures swallowed; app boots anyway.**
  `db/schema.py:340-343` logs and continues after `migrate_database` fails.
  Fix: re-raise so schema drift cannot run silently.
- **F-C7 Snapshot immutability enforced by caller discipline only.**
  `db/database.py:148-154` uses `ON CONFLICT(run_id) DO UPDATE` — the DB layer
  will overwrite a published snapshot if re-published. Consider
  `DO NOTHING`.

## C. BITTER LESSON ASSESSMENT

**Systemic violations:** None of the waste serves the user. The dead
macro-multiplier plumbing, scheduler constants, task-less background manager,
phantom tables, and execution-flavored modals are ego requirements of past
plans that survived their own deletion commit. The stale DOX files are worse
than missing docs: they actively misdirect future agents toward nonexistent
factories, endpoints, and scanners.

**What is load-bearing (do not cut):** the query-only broker surface +
forbidden-member CI scan; the tier→velocity→tiebreaker rank key with composite
score excluded; frozen presets; frozen run snapshots + separate RefreshAttempt
state; complete-union planning gate; `escapeHtml` + safety tests; parameterized
SQL throughout; the rate limiter wiring; offline-deterministic 673-test suite.
These look heavy but each one pins a money-adjacent contract. Leave intact.

**Systemic impact:** Fixing H1-H3 plus the correctness cluster restores full
consistency between what the docs promise and what the code does; the deletion
cluster removes ~600-800 lines without losing capability, making the next
audit boring. Direction: forward, not sideways — nothing here proposes new
capability; it converges the system onto its own stated contracts.

## D. RESEARCHED IMPROVEMENT CANDIDATES (sourced)

Note: an "autoresearch" skill does not exist in this environment; structured
multi-angle web research was used instead.

1. **Display annualized return-on-capital alongside premium velocity, and
   prefer a DTE window (~30-52 DTE) rather than pure shortest-DTE velocity.**
   Velocity biases toward short-dated, high-risk contracts; annualized metrics
   are themselves misleading for short durations, so show both and let the
   preset's DTE window qualify. Maps to `SCORING.md` display block +
   `core/presets.py`.
   Sources: wheelmetrics.io/blog/screen-filter-cash-secured-puts/;
   quantwheel.com/learn/csp-strike-selection/;
   optionjournal.app/site/blog/return-on-capital-option-sellers-annualized-yield
2. **Pin liquidity thresholds to spread-as-%-of-midpoint (≤5-10%), OI ≥500-
   1000, volume ≥100-500** and label them heuristics; verify current preset
   ideals against these practitioner baselines. Maps to preset qualification
   tiers. Source: optionvisualizer.com/documentation/workflows/liquidity-screening
3. **Exit-playbook defaults validated by research:** the implemented ≥50%
   profit-take and ≤21-DTE roll match tastylive's published studies (reduced
   strike-touch probability, similar/noisy P&L difference). Keep, and cite the
   basis in SCORING.md. Sources:
   tastylive.com/shows/tasty-bites/episodes/when-to-exit-01-13-2021;
   tastylive.com/news-insights/options-trading-early-management-touch-probability
4. **Earnings handling already matches best practice** (event tiers block/
   warn pre-expiry; IV-crush and gap risk documented ~20-60% IV collapse).
   Optional sharpening: treat `event_unknown` within 7 days as
   `earnings_before_expiry`-equivalent for staging warnings.
   Source: volradar.com/learn/earnings-iv-crush
5. **OpenD quote freshness architecture:** official docs confirm
   `get_option_chain` returns static metadata and live bid/ask requires
   subscriptions. Current snapshot-polling design is quota-appropriate for
   free tier; if freshness pain persists, add opt-in subscription-based
   refresh for the top-N finalists only. Sources:
   openapi.moomoo.com/moomoo-api-doc/en/quote/get-option-chain.html;
   open.moomoo.com/api/quote/push/rate-limit
6. **Short-volatility framing:** keep the existing "does not claim positive
   expectancy" honesty; research consistently emphasizes asymmetric downside
   and position-sizing discipline over entry selection.
   Source: quantpedia.com/strategies/volatility-risk-premium-effect
