# API Services DOX

## Purpose

`api/services/` owns application-level workflows: Moomoo-backed portfolio/options data, the recommendation engine (backend shortlist authority), watchlists, IV/earnings enrichment (`iv_earnings_service` + `alpha_vantage_provider`), portfolio scoring/context, and roll diagnostics (`roll_diagnostics.py`).

## Ownership

- Own orchestration and adaptation between external data sources, `core` decision helpers, repositories, and route responses.
- Keep durable calculations in `core` when they are independent of Flask or external provider plumbing.

## Local Contracts

- Moomoo/OpenD remains authoritative for portfolio, positions, cash, account state, and option-chain truth.
- Optional providers such as yfinance (fallback quotes) and Alpha Vantage (bulk earnings calendar) may enrich or widen context, but must not silently replace broker truth.
- Services must degrade gracefully when external providers fail, rate-limit, or return partial data.
- Keep caches and TTLs explicit so stale market data is not presented as fresh.
- Do not introduce production mocks or simulated account data.
- When a signal can remain visible only as research-only data, keep that label and caveat explicit rather than silently dropping it.
- Scanner services should return blocker/diagnostic counts when useful so the UI can explain empty panels.
- `RecommendationEngine` is the backend shortlist authority: watchlist coverage is complete-or-planning, executable-return-on-deployed-capital ranking with executable-bid premium velocity as tie-break (quality tiers are display-only risk info and never order; `recommendation_ranking.csp_tail_risk_gate` makes new watchlist CSPs on configured leveraged ETFs, or on single stocks without `event_safe` earnings, research-only before ranking, and `is_roll_target_eligible` lets held positions still roll into such a contract), and candidates carry Moomoo quote evidence plus safe recommended quantity. `/api/run` publishes the immutable result.
- Engine construction hydrates a valid persisted `wheel_preset` before scanning. Missing, invalid, or unreadable settings fall back to configuration; a saved preset must survive service reconstruction and app restart.
- CSP preflight budgets uncached contract-directory ranges against `scan_discovery_budget_sec` (default 900), independently of quote age and cash capacity. Directory reads check memory, then SQLite, then Moomoo; reuse requires the exact US market date. Every underlying is discovered, including at zero cash; all puts across the preset expiry/OTM window are batch-quoted. Successful empty windows count as assessed. Broker failures keep coverage incomplete. A failed discovery or a missing option quote gets one retry in the same run through the same limiter and gate; the discovery retry is skipped when every symbol failed and stops at `scan_discovery_budget_sec`. A symbol that still has no evidence is reported with reason code `broker_data_unavailable` and the broker reason. A covered-call holding whose price or option data cannot be read is reported with the same reason code and `signal_type` `covered_call`; it does not change coverage. Unaffordable candidates are scored in research mode with zero contracts and copy blocked; cash-fitting CSPs precede unaffordable CSPs, and each partition uses the unchanged `rank_key`. Over-budget work remains planning with covered-call diagnostics retained.
- Closed-market CSP and covered-call scans request the freshest available Moomoo/OpenD last-session chain first, then use persisted broker snapshots only as fallback. Complete direct broker evidence can stage despite planning status; incomplete coverage and persisted fallback remain review-only. Staging requires copy-time OpenD confirmation.
- Capital recovery compares stock holdings only; explicit non-stock broker positions do not become share recovery cards.
- `fills_service.py` owns read-only ingestion of broker fills, order fees, and account cash flows for outcome attribution. It only queries (`get_history_deals` / `get_order_fees` / `get_cash_flow`), stamps rows with the opaque account identity from `resolve_portfolio_identity`, persists idempotently via `db.fills_repository`, and allocates order fees across fills proportionally to gross fill value. Attribution math stays in pure `core.outcome_attribution`; reconciled fills may set covered-call basis and income/repair qualification after the measured history-capability gate; fills never reorder recommendations. `campaign_service.py` reads account-scoped persisted fills and explicit current-refresh evidence, preserving broker `avg_cost`. Unverified history falls back to broker basis with named reasons. Each wheel refresh pulls fills once through `refresh_fill_evidence` (owner decision 2026-10-17). OpenD answers at most 90 days per deal query, but older history is reachable: the first pull (or any pull whose covered start is later than `broker_history_start`) backfills in 90-day windows that overlap by one day, with the last window open-ended; a failed window saves nothing and keeps the covered start. The same call then refreshes cash flows: at most 18 clearing dates per refresh (forward from the latest covered day, then backward to the history start, skipped when the forward pass fails), with coverage kept in settings key `broker_history:<hash>:cash_flow_coverage`. `MoomooConnection` paces cash-flow queries below the broker quota of 20 per 30 seconds and history deal queries below the measured quota of 10 per 30 seconds, so a long backfill waits instead of failing. A failed pull logs a warning and does not fail the refresh. Fee backfill resolves at most 40 orders per pull, newest pull first, for every stored order that still lacks fees, and reports the pull incomplete while orders remain. Expiry inference and adjusted basis stay gated while G1 is unmeasured.
- `iv_earnings_service.py` owns the IV environment read: rank and percentile both come from a one-sample-per-day closest-to-ATM series over a 1-year window (`IV_RANK_WINDOW_DAYS`, minimum `IV_RANK_MIN_DAYS` daily samples), never from the raw per-contract rows a scan writes. Fewer samples than the minimum reports `insufficient_history` and applies a zero adjustment rather than a fabricated neutral rank. Both values are display-only and must never gate or reorder candidates. The service also derives `days_to_ex_dividend` (market clock, per C13) for the exit playbook, and `record_iv_data` deliberately does not write the scoring cache — seeding it would publish one contract's rank as the whole ticker's environment for the cache TTL.
- `refresh_stale_event_context` is optional scan enrichment with a 3-second default provider-wait budget and a reused two-worker executor. It returns completed provider results, reports running work as `timed_out` and not-started/already-in-flight work as `deferred`, and deduplicates running jobs by ticker across refreshes. It rotates the stale ticker window by work considered so repeated short budgets do not starve later names, and schedules only into available worker slots; timed-out providers may finish in the background without extending the broker refresh wait. The scan also passes the effective watchlist. One bulk Alpha Vantage calendar job, cached 6 hours, refreshes every stale holding and watchlist ticker (missing, errored, or older than 24 hours) that the calendar lists. Stored ex-dividend dates are kept. Holdings also take the per-ticker path, which carries ex-dividend data. The bulk job is submitted first, does not block per-ticker jobs, and is awaited only for the remaining budget. `get_earnings_info` reports the stored `fetch_status`.
- `outcome_service.py` serves broker-verified outcome summaries on top of ingested fills plus published run snapshots: quoted (recommended) credit vs. filled credit, net-of-fee results, capital-days, and net P&L / capital-day via the pure `core.outcome_attribution` helpers, grouped by preset, DTE bucket, ticker, and event tier. Every aggregate exposes sample size, coverage %, and unknown-outcome count; each outcome record carries its supporting fills for drill-down. A contract is labelled `expired` only when stored G1 evidence is measured with expired-worthless support, and a successful fill pull ran after expiry with a window that began on or before expiry. Otherwise an open contract past expiry is `unresolved_after_expiry` (outcome status `unknown`, capital-days unknown). Matching keys on (ticker, expiration, option_type, numeric strike) so string-formatting drift cannot split one contract. Unknown fees mean an unknown outcome (never zero), unmatched fills are surfaced without a fabricated quoted price, and tiers remain display-only — this service never gates or reorders anything.
- `account_pnl_service.py` reads persisted fills, cash flows, NAV history, and the latest portfolio snapshot from local SQLite (no OpenD) and delegates the math to `core.account_pnl`. It serves `GET /api/options/analytics/pnl`. Unreconciled underlyings keep unknown P&L, never zero.

## Work Guidance

- Prefer dependency injection for config, database, and provider clients in code that needs isolated tests. `roll_diagnostics.build_roll_decisions` receives `iv_earnings` from the app factory; do not reintroduce a service-registry lookup inside a service.
- Before adding or moving a module, assign it to a capability in `docs/architecture/capabilities.json`; run `uv run python scripts/architecture.py docs` and `check`.
- Preserve source metadata and warnings when signals are widened or enriched by non-Moomoo sources.
- Keep recommendation, signal, and risk outputs deterministic enough for regression tests.
- Avoid circular imports back into route modules.

## Verification

- Run the feature-specific service tests for changed files.
- For recommendation/scoring-adjacent service changes, run `pytest tests/test_recommendations.py tests/test_score_regression.py`.
- For provider changes, run `pytest tests/test_routes_earnings.py` plus the matching provider test if one exists.
